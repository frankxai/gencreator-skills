# Source review and product placement — 2026-11-05

## Product decision

**GenCreator Video Breakdown** is a focused workflow inside the existing GenCreator plugin. **Video Intelligence** names the larger capability: reference research, evidence, original production and observed learning. Keep one GenCreator identity. Starlight supplies capability governance and plugin engineering; it is not a competing consumer video brand.

| Reference | Useful behavior | Our disposition |
|---|---|---|
| Brad Marais video-breakdown-skill | Media inspection, timed structure, creator comparisons, transferable templates | Original implementation; no upstream code, prose or taxonomy copied |
| Sandcastles public product and MCP pages | Watchlists, outlier discovery, analysis, scripts and niche patterns through assistants | Competitive baseline; study observable behavior, not undocumented internals |
| Existing GenCreator | Matched cohorts, creator voice, production, revisions and review/learning | Reuse these owners; add only timestamped video evidence and supplier import/planning |
| Apify official API | Actor builds/runs, bounded cost options, dataset pagination | Offline field-mapped export import and capped run proposal now; live execution deferred |

The upstream tree at commit `56570950546af1b3dfb540127065395baef0166c` had no license file. Public access supplies no copying permission. Inspection included its skill workflow, video acquisition design, frame extraction and audio check. We preserve no code or instructions from it. In particular, audio energy is not reliable proof of background music or its absence, and uniformly sampled frames do not establish exhaustive viewing or exact scene cuts.

Sandcastles' public workflow connects channel research, exceptional posts, hook/format analysis and script creation. Its MCP page also describes cross-creator niche insights. These are observed vendor claims, not independently verified product tests. We did not access a private workspace, reverse engineer its scoring or verify its training/data architecture. No inference about its internal algorithms is used as a design fact.

## Differentiation to validate

The proposed advantage is continuity of judgment: a claim opens its source moment; a creative decision retains the creator's original proof and voice; an edit produces a new revision; production and observed results refer to the same packet. Avoid “viral certainty,” undifferentiated hook volume and blended cross-platform scores. Design a counterexample alongside every winning-pattern hypothesis.

For a creator, the useful output is an original, shootable next video with a single measurable hypothesis. A reference is a source of mechanics, not a surrogate for authorship. No new generation provider, editor, scheduler or media store is introduced by the plugin extension.

## Integration ownership

| Stage | Owner and implemented boundary |
|---|---|
| Import/plan | New offline helper; explicit actor map and lineage; no credential or network access |
| Inspect | Host media/image/audio tools; extraction emits hashes and uninspected state |
| Compare | Existing gencreator-outlier-analysis; no second scoring system |
| Original brief | New breakdown skill with supplied CreatorPack reference |
| Voice/production | Existing voice, produce and reference-to-commission workflows; conditional handoff |
| Editing/rendering | Existing video engine or authorized creator tools; separately invoked |
| Approval/release | Existing actual revision-bound approval owner; no new authority |
| Observe/learn | Existing review-and-learn; accepted lessons only |

The portable production packet is not an authenticated server import. Exact managed Creator Mission admission, tenant enforcement, persistent watchlists and result collection still require engineering and runtime evidence. Existing GenCreator MCP wiring is preserved; no endpoint is invented.

## Commercial posture

Keep local breakdown and export useful with the creator's existing model account. The proposed managed value is persistent research collections, team reviews, recurring verified observations and CreatorPack learning. Do not resell the user's existing ChatGPT, editing or generation subscription. Provider collection costs need a visible per-job cap and actual receipt; test paid features only after activation and margin evidence. This extension enables no price, checkout, subscription or recurring collection.
