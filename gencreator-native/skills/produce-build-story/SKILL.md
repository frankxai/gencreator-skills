# Produce build story

## Inputs and work
Require the current artifact revision, intended audience, user consequence, approved claims, owned/cleared media, useful destination and actual capture/edit tools. Open the artifact. Verify what the audience can do and what the recording must not imply. A proposal can be demonstrated as a proposal; replay/prototype labels must remain in frame.

Write a natural 30–60 second spoken story (45 seconds by default): visible result, human consequence, one consequential choice, actual interaction, limits and useful next action. Show the result before the implementation detail. Avoid generic superiority claims and manufactured contrast hooks. Keep source and exact-edition approval attached.

Plan 5–7 shots with durations, on-screen action/crop, narration, capture requirements and captions. Capture through real available tools; assemble an editable timeline or source project and render when supported. Reuse installed video-social-studio deterministic media tools when available. Inspect playback, legibility, timing and audio. Mark no-voice or placeholder-sound editions explicitly.

## Output and acceptance
Deliver spoken script, 5–7 shot plan, captured source inventory, captions (editable SRT/VTT), thumbnail treatment, sound direction, useful destination, editable assembly and actual render/recording where executed. State separately `script`, `recorded`, `edited draft`, `approved revision`, `published`; provide evidence for each advanced state.

Pass example: a 45-second editable six-shot recording of the inspected prototype shows its saved-run label and opens the real result; narration/captions do not imply a live run. Fail example: a script reported as a rendered Reel, decorative pans reported as a screen capture, or missing audio called a finished voiced edit.

## Failure and boundaries
No capture access: return the precise ready-to-record package and mark recording pending while completing independent script/caption work. Failed/uncertain generation: retain job evidence and do not repeat paid submissions. Unknown music/likeness rights block reuse. Never publish, message, spend or switch accounts based on this skill alone. New visual families retain founder selection gates.

Read [commission contract](../reference-to-commission/references/commission-contract.md) before changing state. Load [tool routing](../reference-to-commission/references/tool-routing.md) only when a connected surface is needed. Reuse the same commission ID and compare the current revision immediately before every dependent action. Keep technical validation, source rights, founder selection and release state separate.

When supplied by the private account package, read `skills/reference-to-commission/references/private-guidance.md` from the plugin root for approved task-scoped source projections. Its approval/freshness states remain authoritative; a missing projection is a named gap.
