# Run workflow experiment

## Inputs and work
Require a current selected commission, baseline, target outcome, actual stack, resource limits, rollback and selection authority. Read AGENTS and relevant implementation files. Inspect available helpers/components before adding code, dependencies or infrastructure. For nonvisual work, compare real input/output and process friction rather than forcing UI treatments.

Build the smallest useful trial in an isolated branch/worktree or retained artifact revision. Keep one owner for shared writes. Use existing stack and deterministic helpers for mechanics; reserve model judgment for semantics. Check dependencies, pin/licensing and upstream docs only when needed by the actual change.

Run the relevant checks and inspect the result in its actual medium. Capture before/after at required viewport/ratio and critical states, or a nonvisual input/output diff. Label fixture, prototype and replay visibly. Record executed commands, tool receipts, cost when observed (otherwise null), limitations and rollback. No passing unit test establishes user benefit or field performance.

## Output and acceptance
Return a running artifact or focused diff/preview, exact source revision, baseline/candidate evidence, executed checks separated by deterministic/model/tool/human type, actual observed cost, known limits, rollback and keep/revise/reject reuse proposal. Distinguish implemented, previewed, merged, deployed and operating.

Pass example: an existing replay gains an accessible evidence inspector and opens its actual output; mobile and keyboard checks pass, absent diagnostics stay absent. Nonvisual pass: a source-backed editorial packet deduplicates three supplied references and exports a usable revision without claiming publication. Fail example: a static proposed architecture labeled a live agent, or a test fixture described as a customer outcome.

## Failure and boundaries
On stale guidance/commission revision, stop dependent execution, retain the diff and refresh. On unsupported tool or build failure, return the concrete error and a useful smaller fallback; do not replace the stack to evade failure. Stop after two repair rounds or the resource cap. Create no new server/database without an observed missing capability. Production deployments/publication and new spending require their actual authority.

Read [commission contract](../reference-to-commission/references/commission-contract.md) before changing state. Load [tool routing](../reference-to-commission/references/tool-routing.md) only when a connected surface is needed. Reuse the same commission ID and compare the current revision immediately before every dependent action. Keep technical validation, source rights, founder selection and release state separate.

When supplied by the private account package, read `skills/reference-to-commission/references/private-guidance.md` from the plugin root for approved task-scoped source projections. Its approval/freshness states remain authoritative; a missing projection is a named gap.
